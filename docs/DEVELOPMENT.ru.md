# gwm-stats-switch — sysmodule для прошитой Switch

На самой консоли модуль называется коротко **gwm-stats**; расширенное имя
репозитория отличает Switch-клиент от сервера и других клиентов.

Sysmodule для прошитой Nintendo Switch (Atmosphere / UltraNX), которая репортит
игровую активность на сервер gwm-stats по контракту
`docs/ingest-api-v1.md`.

Ставится один раз и работает сам — **инструкция с нуля** ниже, в разделе
[Установка с нуля](#установка-с-нуля).

Работает в фоне рядом с игрой, стартует с системой, ничего не требует от
Nintendo: ни NSO, ни выхода на серверы Nintendo. Весь трафик идёт только на твой
сервер.

**Состояние: работает.** Текущая версия — 1.0.0 (по коду 1.2.1), живьём проверена на одной
консоли (Switch, Atmosphere); если запустишь на своей, расхождения интересны.
Первым рабочим релизом была 0.5.5: до 0.5.2 модуль не отправлял на сервер ни
одного байта — подключался за шесть миллисекунд и молча вставал внутри `send`
из-за урезанных сокетных буферов. Всё, что до 0.5.5, интересно только истории.

## Семейство репозиториев

Этот sysmodule — один из клиентов gwm-stats. Вся доменная логика (дедуп,
сессии, трофеи, live-статус, дашборд) живёт на сервере; клиент только шлёт
события по ingest API.

| Репозиторий | Роль |
| --- | --- |
| gwm-stats | сервер и контракт ingest: `docs/ingest-api-v1.md`, для авторов клиентов — `docs/ingest-api-v1-client.md` |
| **switch-playtime-tracker** (этот репозиторий) | клиент: Atmosphere-sysmodule для прошитой Switch |
| [ps3-playtime-tracker](https://github.com/gowithme-club/ps3-playtime-tracker) | клиент: VSH-плагин для PS3 (CFW / PS3HEN), тот же ingest |
| gwm-stats-ios | приложение для iOS: читает публичный API сервера, в ingest не пишет |

Изменение серверного поведения или самого контракта — в gwm-stats, не здесь.
PS3-клиент решает те же задачи на другой консоли: если вопрос про поведение
ingest (дедуп, watermark, формат тел), полезно сверяться с ним.

## Что уже умеет

- **Heartbeat** (`POST /ingest/v1/heartbeat`) — «кто играет прямо сейчас»:
  title id, время начала сессии и имя игры, если консоль его отдала. Раз в
  минуту плюс немедленно при смене игры.

  Про имя: модуль просит у `ns` только NACP, без иконки на 128 КБ, и на многих
  консолях сервис такой урезанный запрос отклоняет (`0x5010`) — тогда игра
  уходит одним title id, а название подставляет сервер. Читать NACP вместе с
  иконкой модуль умеет и делал это в 0.5.0, но под такой буфер нужна куча в
  512 КБ, а с ней перестают открываться аплеты (см. раздел про память).
- **Профиль консоли** — на консоли обычно несколько пользователей, и модуль
  спрашивает журнал воспроизведения самой консоли (`pdm`), кто запустил игру:
  там у события лежат и профиль, и id приложения. Ник уходит в поле `account`,
  на сервере каждый профиль — свой аккаунт (`switch:<deviceId>:<профиль>`), так
  что время не сваливается в кучу владельцу.

  Именно журнал, а не «последний открытый пользователь» из `acc`: тот называет
  **предыдущего** игрока, потому что игра открывает свой профиль в середине
  собственной загрузки — позже, чем модуль замечает запуск. Журнал ищется только
  за текущую сессию: он помнит все запуски за всю жизнь консоли, и без границы
  по времени отвечает тем, кто играл в эту игру в прошлый раз. Пока владелец
  сессии не определён, она не репортится вовсе — лучше значок с опозданием на
  пару секунд, чем чужая сессия в базе.

  Отсюда одна особенность, которую стоит знать заранее: **если включить модуль
  поверх уже запущенной игры, у этой сессии владельца не будет**. Границей
  поиска служит момент, когда модуль заметил игру, а событие входа аккаунта
  осталось в журнале раньше — до включения модуля. В логе это видно как
  `pdm=- open=- last=-`. Лечится само при следующем запуске игры: выйдите в
  меню и зайдите обратно, и сессия определится с первой попытки. То же самое
  касается закрытых сессий из журнала — те, что консоль не может привязать к
  аккаунту, не отправляются, и в логе о каждой пишется строка `Dropping`.

  С 0.5.7 у этого есть страховка на случай, когда журнал молчит не по
  случайности, а всегда: хоумбрю-порты и форвардеры с самодельным title id
  (`03DB…` вместо `0100…`) вообще не спрашивают профиль при запуске, поэтому
  событию аккаунта в журнале взяться неоткуда. Если на консоли всего один
  профиль, берётся он — выбирать не из чего. Если профилей несколько, работает
  `defaultUid` из конфига: владелец заранее говорит, на кого писать такие
  запуски. Без `defaultUid` поведение прежнее — `Dropping`.
- **Сон/просыпание** — перед засыпанием, пока Wi-Fi ещё жив, шлёт пустой
  heartbeat, чтобы live-статус погас сразу, а не по 5-минутному TTL сервера.
  Время сна не засчитывается в «играет N минут».
- **Коррекция часов** — сервер режет таймстемпы из будущего, поэтому смещение
  вычисляется из заголовка `Date` каждого ответа и применяется ко всему, что
  уходит на сервер. На консоли с исправными часами оно равно нулю (в логе тогда
  нет ни строки про него, пишется только изменение). Ненулевым оно становится
  там, где заблокированы серверы Nintendo — синхронизация времени идёт через
  них, галочка «синхронизировать по интернету» при этом стоит, но упирается в
  пустоту, и консоль живёт на своих часах.
- **Закрытые и офлайн-сессии** — после heartbeat модуль читает завершённые
  фрагменты локального `pdm:qry` и отправляет их в
  `POST /ingest/v1/switch/play-sessions`. В них остаются исходные события
  запуска, фокуса, закрытия и аккаунта; длительность, владелец, фильтрация и
  дедупликация вычисляются сервером. Поэтому несколько часов или дней без сети
  не теряются: журнал остаётся на консоли, а backlog догружается батчами после
  возвращения связи.

  При первом запуске серверный watermark пуст, и модуль выгружает журнал с
  самого начала — всю историю консоли, по две сессии в батче и три батча
  после каждого heartbeat, то есть примерно шесть сессий в минуту, пока
  консоль включена. Тысяча запусков — это часа три; старые игры появляются
  на профиле постепенно.

  Журнал помнит все запуски за всю жизнь консоли — на тестовой их 26 499, — и
  читать его целиком под каждую отправку выходило по 13 секунд, потому что
  каждые 32 записи это отдельное обращение к внутренней памяти. Нужное всегда в
  хвосте, так что с 0.5.5 начало ищется бисекцией: ~1,5 секунды вместо 13. Что
  именно отправляется, при этом не изменилось.
- **Горячая перезагрузка конфига** — файл перечитывается при изменении, консоль
  перезагружать не надо.

## Память: почему это важнее, чем кажется

Сисмодуль резервирует свою кучу на всё время работы консоли, и берётся она из
того же системного пула, из которого система выделяет память **аплету** — когда
игра открывает браузер (соглашение, политика конфиденциальности, вход в аккаунт)
или альбом. Не хватило — падает не наш модуль, а первый, кто в этот момент
попросил ресурс, и вместе с ним игра.

Проверено 2026-08-14 на живой консоли: Ni No Kuni стабильно роняла систему на
экране политики конфиденциальности (`hid`, `2001-0132` LimitReached, три отчёта
в `/atmosphere/fatal_reports/` с точностью до байта одинаковые), и та же игра
проходила это место, стоило выключить модуль в меню sysmodules.

Что с этим сделано:

- **Резерв кучи — 320 КБ** (`INNER_HEAP_SIZE 0x50000`) вместо унаследованных
  512 КБ. Диапазон нащупан с обеих сторон живыми проверками: на 128 КБ потоку
  psc не хватает стека и модуль не стартует, на 512 КБ открывается альбом, но
  Ni No Kuni вешает консоль при открытии внутриигрового браузера — музыка играет,
  картинка стоит, а это ровно то, что делает аплет, которому отказали в памяти.
  На 320 КБ открывается и то, и другое.
- **Никакого TLS.** Только `http://`, конфиг с `https://` отклоняется при
  загрузке. Тащить TLS-стек в память консоли — та самая цена, которую платит
  браузер в игре.
- **Сервисы открываются по месту.** `acc` и `pdm:qry` берутся и отдаются вокруг
  каждого обращения, а не держатся с загрузки.

**А вот сокетные буферы трогать нельзя, и это не оговорка.** Раньше здесь было
написано обратное — что их надо ужимать ради системного пула, — и это стоило
проекту месяцев. Урезанные буферы не делают сеть медленной: драйвер BSD молча
останавливается **внутри `send`**, без ошибки и без таймаута. Модуль подключался
к серверу за шесть миллисекунд и не отправлял ни байта. libnx считает размер
блока как `page_up(tcp_tx_max + tcp_rx_max + udp_tx + udp_rx) × sb_efficiency`,
и в собственном комментарии предупреждает, что ниже нужного размера сервис шлёт
только ZeroWindow-пакеты, то есть не более байта в секунду. Сейчас стоят
значения SwitchRPC — 128 КБ, — и они работают. Если всё-таки понадобится их
двигать, то `sb_efficiency` по одному шагу и с проверкой реального POST на
консоли после каждого.

**`https://` не поддерживается**, только `http://` (контракт ingest это
разрешает). Конфиг с `https://`
отклоняется сразу при загрузке — в логе одна строка про отсутствие TLS, и модуль
идлит; молча принять такой адрес значило бы отчитаться об успешной загрузке и
валить каждый запрос.

Отсюда следствие, которое надо понимать, если сервер стоит не в локальной сети:
**токен устройства уходит по открытому HTTP**. В пределах домашней сети это
приемлемо, через интернет — нет, если содержимое имеет для тебя цену. Терминация
TLS на стороне сервера (обратный прокси, туннель) эту проблему не решает: до
прокси трафик всё равно идёт открытым.

## Установка с нуля

### Что понадобится

- **Прошитая Switch** с Atmosphere (CFW). На стоковой консоли модуль не работает
  и работать не может.
- **SD-карта из этой консоли** и возможность прочитать её на компьютере —
  картридер или переходник.
- **Токен устройства** — выпускается на [gowithme.club](https://gowithme.club)
  в карточке «Nintendo Switch (CFW)» и показывается один раз. Без токена модуль
  запустится, напишет в лог `token is empty — idling` и не будет делать ничего.

### Шаги

1. **Скачай архив** `gowithme-club-switch-<версия>.zip` со страницы
   [Releases](https://github.com/gowithme-club/switch-playtime-tracker/releases) — он лежит
   внизу описания релиза, в разделе **Assets**.
2. **Выключи консоль полностью**: зажать кнопку питания → Power Options → Turn Off.
   Спящий режим не подходит. Вынь SD-карту.
3. **Вставь карту в компьютер** и распакуй архив.
4. **Скопируй папку `atmosphere` из архива в корень карты.** Папка `atmosphere`
   там уже есть — на вопрос отвечай **объединить** (Merge / Слияние), а не
   «заменить»: внутри архива только `atmosphere/contents/4200000000505341/`,
   ничего чужого не пострадает. Должно получиться так:

   ```
   atmosphere/contents/4200000000505341/exefs.nsp
   atmosphere/contents/4200000000505341/toolbox.json
   atmosphere/contents/4200000000505341/flags/boot2.flag
   ```

5. **Создай на карте файл** `config/gowithme.club/config.json` (папку
   `gowithme.club` внутри `config` тоже нужно создать) и положи в него:

   ```json
   {
     "token": "токен устройства с сервера"
   }
   ```

   Больше ничего не нужно: адрес сервера (`http://gowithme.club`) зашит в
   модуль. Остальные ключи необязательны и описаны в разделе [Конфиг](#конфиг).
6. **Верни карту в консоль и включи её.** Модуль стартует сам вместе с системой —
   благодаря файлу `flags/boot2.flag` из архива. Никаких иконок и окон он не
   показывает: он работает в фоне.
7. **Проверь, что он жив.** На карте появится файл
   `config/gowithme.club/log.txt`; открой его (или прочитай по FTP, если он
   настроен). Первые строки должны выглядеть так:

   ```
   --- gwm-stats-switch sysmodule started ---
   [10:12:01] [Init] switch-plugin/1.2.0 started (heap 320 KB).
   [10:12:01] [Config] Loaded: url=http://gowithme.club ...
   [10:12:01] [Http] Transport works through curl (switch-plugin/1.2.0).
   ```

   Дальше запусти любую игру и посмотри на дашборд сервера — через минуту там
   должен появиться живой статус.

### Если что-то пошло не так

Всё, что нужно, пишется в `config/gowithme.club/log.txt` на карте. Это первое
и обычно единственное место, куда стоит смотреть.

| Что в логе | Что это значит |
| --- | --- |
| файла лога нет вообще | Модуль не запустился: проверь, что на карте есть `atmosphere/contents/4200000000505341/exefs.nsp` и файл `flags/boot2.flag` рядом с ним, и что консоль загружена с CFW, а не в стоке. |
| `token is empty — idling` | Не найден или пуст `token` в `config/gowithme.club/config.json` — шаг 5. |
| строка про отсутствие TLS | В `ingestUrl` стоит `https://`. Нужен `http://`. |
| `Couldn't resolve host name` | Консоль не смогла разрешить имя сервера (частая история с 90DNS). Впиши в конфиг `"ingestUrl": "http://<IP сервера>"` вместо имени. |
| лог есть, но версия старая | На карту лёг не тот `exefs.nsp`, либо консоль загрузилась со старой карты. |
| игра идёт, а на сервере тихо | Сессия не отправляется, пока модуль не понял, чей это профиль. Загляни в конец лога: там будет либо `Dropping`, либо строка про выбранный профиль. Помогает ключ `defaultUid` — см. [Конфиг](#конфиг). |

### Как обновить

То же самое: скачать новый архив, скопировать папку `atmosphere` в корень карты
поверх старого (**заменить** файлы), включить консоль. Конфиг не трогается.

Если консоль перезагружать не хочется, а модуль надо перезапустить — это делается
в оверлее **Sysmodules** (Ultrahand/Tesla): выключить `gowithme.club` и включить снова.
Новая версия видна по первой строке лога.

### Как выключить или удалить

Выключить на время — тем же оверлеем Sysmodules. Удалить совсем — стереть с карты
папку `atmosphere/contents/4200000000505341`. Логи и конфиг останутся в
`config/gowithme.club/`, их можно удалить отдельно.

## Конфиг

`sdmc:/config/gowithme.club/config.json`. Старая папка
`config/gwm-stats-switch/` (до 1.2.0) читается, если новой нет — карту,
настроенную раньше, переделывать не нужно; лог и маркер пробы всегда пишутся
в новую.

```json
{
  "token": "токен устройства с сервера",
  "ultrahandNotify": false,
  "ingestUrl": "http://192.168.1.10:3300",
  "accounts": {
    "0123456789ABCDEF0123456789ABCDEF": "Alex",
    "FEDCBA9876543210FEDCBA9876543210": "Sam"
  },
  "defaultUid": "0123456789ABCDEF0123456789ABCDEF"
}
```

Обязателен только `token`. Всё остальное — тонкая настройка, и обычному
человеку она не нужна.

- `token` — токен устройства, уезжает в `Authorization: Bearer`.
- `ultrahandNotify` — тосты Ultrahand Overlay, с 1.2.0 по умолчанию вкл.
  Нужны UltraNX/Ultrahand и включённые API Notifications в самом оверлее;
  модуль только кладёт JSON в `/config/ultrahand/notifications/` — и только
  если эта папка уже есть: её создаёт сам Ultrahand (с 2.1.0, где API
  уведомлений и появился), и никто другой. Uberhand — форк Ultrahand, который
  ставят Kefir и 4IFIR, — живёт в том же `/config/ultrahand/`, но уведомлений
  не знает, поэтому проверка именно на подпапку: без читателя ничего не
  пишется и ничего не копится. Показывается не каждый heartbeat, а
  редкие события: первый отчёт новой сессии («Играет: Fire Emblem™: Three
  Houses») и принятые закрытые сессии — до трёх штук по одной — название игры,
  а под ним «1 ч 23 мин · всего 41 ч 10 мин», где «всего» — то же, что в
  Telegram-карточке сессии, — больше трёх — одной строкой («Сессий ушло: 12,
  всего 9 ч 40 мин»). Сессии, закончившиеся больше двух суток назад, тостов
  не получают: это журнал консоли выгружает историю (см. ниже), а не то, во
  что человек только что играл. Название и длительность приходят от сервера в
  ответах на heartbeat и на пачку сессий — консоль своих названий не знает,
  см. раздел про имена; от сервера, который этих полей ещё не отдаёт, в тосте
  будет голый id. Если тостов нет вообще, первым делом проверь API
  Notifications в самом Ultrahand (Settings → Notifications, или удержать
  `MINUS` ~4 с — этот же хоткей их и выключает случайно): при выключенных он
  молча удаляет файлы из папки. Tesla-Menu и Uberhand (Kefir, 4IFIR) этого
  механизма не знают — только Ultrahand/UltraNX 2.1+.
- `ingestUrl` — куда слать; по умолчанию `http://gowithme.club`, и ключ нужен
  только для сервера, поднятого у себя. База без хвостового слеша, схема
  только `http://`; пути `/ingest/v1/*` добавляются сами. Хостнейм работает
  начиная с 0.5.3 — до неё
  резолв всегда падал с `Couldn't resolve host name`, и виноват был сам модуль,
  а не консоль: libnx открывает `sfdnsres` под каждый запрос через живую сессию
  `sm`, а модуль её закрывал на старте. Теперь `sm` держится на время запроса.
  Если у тебя стоит 90DNS и резолв всё же не работает, впиши IP — по нему
  резолвер не зовётся вовсе.
- `accounts` — необязательные стабильные соответствия UID профиля имени на
  сервере. Они переживают переименование Switch-профиля и применяются и к live,
  и к ретроспективным сессиям. UID виден в логе модуля; ключ — 32 шестнадцатеричных
  символа без разделителей.
- `defaultUid` — UID профиля, на который записывать запуски, которые консоль
  никому не приписала. Так выглядит хоумбрю-порт или форвардер с самодельным
  id: он не спрашивает профиль, а значит и не открывает его, и в журнале `pdm`
  нет ни события аккаунта, ни статистики по пользователю. До 0.5.7 такие
  закрытые сессии просто выкидывались (`[Journal] Dropping …`), а живая сессия
  падала на «профиль, открытый до запуска». Формат тот же, что у ключей
  `accounts`: 32 шестнадцатеричных символа. UID сверяется со списком профилей
  консоли — опечатка не создаст несуществующего человека, а просто отключит
  фолбэк. Поле необязательное; если профиль на консоли ровно один, он берётся
  и без него, потому что там выбирать не из чего.
Ключи `account`, `heartbeatSeconds` и `caBundle` из старых конфигов
игнорируются: запасное имя профиля теперь всегда `switch`, интервал heartbeat —
минута, TLS в модуле нет. Файл с ними продолжает работать.

Сессию без известного профиля (ни один не открывали с момента загрузки) модуль
подписывает как `switch`; в логе такая сессия помечена явно.

## Сборка

Нужен devkitPro с `switch-libjson-c` и `switch-curl`:

```bash
dkp-pacman -S switch-libjson-c switch-curl
make            # -> dist/atmosphere/contents/4200000000505341/
```

`dist/` — это готовая раскладка для корня SD-карты плюс `README.txt` с краткой
инструкцией и ссылками на поддержку (из `README.dist.txt`), ровно та, что лежит в архиве
релиза. `make -C gwm-stats-switch` собирает модуль без раскладки.

Версия берётся из файла `VERSION` в корне: она печатается первой строкой лога,
уходит в `User-Agent` как `switch-plugin/<версия>` и в `X-Client-Version` голой (сервер
показывает её на странице статуса рядом с устройством) и стоит рядом с именем
модуля в оверлее Sysmodules.
Перед релизом меняется это одно значение; сборка остановится, если версия в
`gwm-stats-switch/toolbox.json` ему не соответствует.

## Обновление сборки

Файлы кладутся по FTP (`ftp://192.168.1.37:5000` — это корень SD-карты), после
чего модуль перезапускается вручную через Sysmodules:

```bash
curl -T gwm-stats-switch/gwm-stats-switch.nsp \
  ftp://192.168.1.37:5000/atmosphere/contents/4200000000505341/exefs.nsp
```

**Версия живёт в двух файлах, и залить надо оба.** `exefs.nsp` — это сам модуль,
его версию печатает первая строка лога. `toolbox.json` — это подпись рядом с
модулем в меню Sysmodules, и на работу она не влияет вообще. Забыть про второй
легко, и тогда меню месяцами показывает версию, которой давно нет:

```bash
curl -T dist/atmosphere/contents/4200000000505341/toolbox.json \
  ftp://192.168.1.37:5000/atmosphere/contents/4200000000505341/toolbox.json
```

Перед заливкой имеет смысл переименовать то, что заменяешь, — тогда откат стоит
одного переименования обратно:

```bash
curl -Q "RNFR /atmosphere/contents/4200000000505341/exefs.nsp" \
     -Q "RNTO /atmosphere/contents/4200000000505341/exefs.nsp.pre-0.5.5" \
     ftp://192.168.1.37:5000/
```

Оттуда же читается лог, не вынимая карту:

```bash
curl -s ftp://192.168.1.37:5000/config/gowithme.club/log.txt | tail -40
```

Раньше эту роль играл отдельный dev-only sysmodule `gwm-reloader` (Title ID
`4200000000505342`), который перезапускал модуль по команде из локальной сети.
Он удалён: его слушающий сокет намертво вставал в `poll`. Вторая половина
обвинения — что занятый им `bsd:s` вешал и сетевые вызовы самого `gwm-stats` —
оказалась неверной: запросы вставали по своей причине, из-за урезанных сокетных
буферов (см. раздел про память), и продолжали вставать после удаления
`gwm-reloader`. История есть в git, если захочется вернуться к идее.

## Происхождение

Модуль — производная от [llsc12/SwitchRPC](https://github.com/llsc12/SwitchRPC)
(MIT), откуда взят каркас sysmodule: права в npdm, размер heap, конфигурация
сокетов, протокол работы с psc и коррекция часов по заголовку `Date`. Discord-часть
удалена целиком и заменена на клиент нашего ingest API. Лицензия сохранена, см.
[LICENSE](../LICENSE).

Чтение play-событий опирается на формат libnx и алгоритм
[NX Activity Log](https://github.com/tallbl0nde/NX-Activity-Log): сессия идёт от
launch до exit (или следующего launch после сбоя), а игровое время — сумма
интервалов in-focus → out-of-focus по steady clock.
